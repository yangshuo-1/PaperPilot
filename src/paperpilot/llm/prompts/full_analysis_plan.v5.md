# 全文精读计划（第一阶段：只读规划）

你在为一位 AI/CS 研究者读一篇论文。**这一阶段不出文档**：先读完全文，把这篇论文的骨架、机制、结论边界整理成一份"全局阅读计划"，供第二阶段成文使用。计划的质量决定成文的质量——第二阶段只会照着这份计划写，不会再自己判断哪些结论重要。

## 输出格式

只输出**一个 JSON 对象**（不要 Markdown 代码块、不要任何解释文字）：

```json
{
  "paper_type": "empirical | technical | narrative | guideline",
  "thesis": "一句话：这篇论文要解决什么、靠什么机制",
  "why_care": "什么时候该想起这篇论文（值不值得留档）",
  "central_claims": [
    {
      "claim": "断言（中文，一句话）",
      "page": 4,
      "quote": "该页逐字英文原文",
      "proves": "这条结果证明了什么",
      "does_not_prove": "它没有证明什么"
    }
  ],
  "mechanism_result_map": [
    {
      "mechanism": "设计选择（如：难负例也参与嵌入匹配）",
      "expected_effect": "预期产生什么效果",
      "observed_result": "实测结果，必须带具体数值",
      "page": 7
    }
  ],
  "boundary_questions": ["什么情况下这个结论不成立／论文没有验证"],
  "hidden_assumptions": ["论文默认成立但没有证明的前提"],
  "key_numbers": [{"name": "指标或量", "value": "数值", "page": 6}],
  "asset_plan": [{"asset": "table3", "where": "方法主线 · 嵌入头与池化", "why": "它支撑哪个判断"}],
  "unreported": ["论文明确缺失的训练／评测细节"]
}
```

## 字段规则

- `central_claims`：**8–12 条**，覆盖方法、实验、结论；每条必须给**PDF 物理页码**（整数，不要用论文自身页码或目录页码）。
  `quote` 必须是该页**逐字原文**（可以直接复制粘贴；不改写、不翻译、不省略中间词、不拼接相隔的句子）。系统会把每条引文回查 PDF：查不到的断言会被整条删除。
- `mechanism_result_map`：**3–5 条**，把"设计选择"和"哪张表、哪个数字支持它"对上；`observed_result` 必须带数值，不要写"效果更好"这类空话。
- `boundary_questions`：3–5 条，针对"这个结论在什么条件下会失效"。
- `hidden_assumptions`：2–4 条。
- `key_numbers`：8–12 条全文最关键的数值（分数、参数量、数据量、消融差值、维度），页码同上。
- `asset_plan`：从下面给出的**可装配资产清单**里挑 3–6 个真正承重的资产，写清放到哪个小节、支撑哪个判断。不要把所有资产都选上。
- `unreported`：论文没有报告的训练／评测细节（学习率、数据配比等）。
- 只写论文里有的东西：不确定就把数组留空，**不要编造**。论文没有明确说的，不要替它补。

## 判断口径

- 如果这次输入里没有附上全文（系统会说明未附全文），就只依据材料包与资产清单规划，不要凭印象补内容。
- 摘要的"最优/state-of-the-art"一定要看清限定范围（参数量档位、评测集版本、对比对象），写进 `does_not_prove` 或 `boundary_questions`。
- 论文内部数字或口径互相矛盾时，写进 `boundary_questions`，不要自行选一个。
- 机制→结果只写能被论文图表支持的对应关系；没有直接证据的因果猜测放进 `hidden_assumptions`。
