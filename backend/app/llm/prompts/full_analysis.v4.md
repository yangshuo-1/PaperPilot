# 论文全文解析分片引擎（prompt v4）

你在为 `paper_valt` 生成论文的「全文详细解析」。你**一次只处理论文的一个连续页片段**（由 `PP. 起页-止页` 标出），最终文档由确定性代码把各片段的结果拼装而成。

v4 相对 v3 的变化：**从「必须写够」升级到「必须能读」**。v3 解决了正文过薄，但产物的排版仍像审计报告——页码钉在每句话中间、同一事实在多个主题下反复出现、遇到表格就写「需人工核对」。v4 把这三件事写进规则，并要求正文直接引用图/表/式编号，因为图、表、公式由确定性代码从论文 LaTeX 源码装配进笔记，不需要你在正文里替读者回避它们。

## 你能看到的输入

- 论文元数据（标题、短标题、paper_id、PDF 总页数、document_version）。
- 该片段的逐页抽取文本，每页以 `===== 第 N 页 =====` 开头。

## 你必须输出的内容

只输出一个 JSON 对象，不要 Markdown 代码块、不要注释、不要额外说明文字：

```json
{
  "narrative": [
    {
      "section": "method",
      "topic": "训练配方",
      "text": "EmbeddingGemma 用三种损失联合训练：带 in-batch negatives 的 NCE 对比损失、受 GOR 启发的 spread-out 正则项，以及从 Gemini Embedding 蒸馏的 embedding matching 损失。hardness weight 让模型更关注当前难以区分的 query–hard negative 对，stop-gradient 阻止梯度穿过权重因子本身，因此权重只反映当前难度、不会把「难度」也一起优化掉。spread-out 正则只保留原 GOR 的二阶矩项，作者认为这已足以把一阶矩推向目标值，同时让嵌入对量化更鲁棒。（第 4 页）"
    }
  ],
  "blocks": [
    {
      "section": "method",
      "topic": "训练配方",
      "claims": [
        {"text": "一条结论式陈述（中文）", "page": 4, "quote": "支撑该陈述的英文原文，逐字摘录"}
      ]
    }
  ],
  "figures_tables": [
    {"page": 7, "kind": "table", "note": "该表报告了什么；只写你能从抽取文本确认的内容，无法确认就写 无法从抽取文本确认"}
  ],
  "gaps": ["本片段中无法确认、或文本抽取明显不完整的地方"]
}
```

## 一、排版规则（v4 核心要求）

**页码**：

- 页码只写在**段末**，一段最多一处，格式 `（第 3 页）`、`（第 3-4 页）`；禁止把 `（第 N 页）` 插在句子中间。
- 一段讲同一页或相邻页的内容，只在段末标一次；不要一句一标。

**不重复**：

- 同一事实、同一数值、同一设计说明**只在最合适的那个 `topic` 下写一次**。发现自己在另一个 topic 下又要讲同一件事时，不要重复，改讲该 topic 独有、正文还没写过的内容。
- 不要用同义改写把同一段话写成两段。文档是给人读的：读者第二次读到同一件事就是噪音。

**图表与公式**：

- 正文直接引用编号：`表 1`、`图 1`、`式 2`。编号按论文 LaTeX 源码中的出现顺序（即论文自己的编号）。
- **禁止**再写「需人工核对 PDF 表格」「具体数值需人工核对」「表格数值在抽取文本中错位」作为正文句子：表格数值由确定性代码取自 LaTeX 源码并装配进笔记。抽取文本确实读不出内容时，把这件事写进 `gaps`，正文只讲能从文本确认的结论。
- 论文没有编号（或你无法确定编号）时，写「该表/该图」并给出页码，不要编造编号。

**术语与数字**：保留论文原有指标名、模型名与数值（不换算、不四舍五入）。中文与英文术语之间不要塞空格，`表 1`、`图 2` 这类引用保留一个空格。

## 二、章节必须写足深度

`narrative` 是文档正文。**只要本片段出现了某个章节的内容，就必须写足下表的下限**：

| section | 中文名 | 本片段最少叙述字数 | 最少段数 |
| --- | --- | --- | --- |
| `abstract` | 摘要 | 300 | 1 |
| `background` | 背景 | 300 | 1 |
| `related_work` | 相关论文/相关工作 | 250 | 1 |
| `method` | 方法 | 700 | 2 |
| `experiment` | 实验 | 700 | 2 |
| `conclusion` | 结论 | 300 | 1 |
| `limitation` | 局限性 | 250 | 1 |
| `reproduction` | 复现与工程建议 | 250 | 1 |

- 本片段若包含论文的方法或实验正文，该片段 `narrative` **合计不少于 1500 字**。
- 每段 200–600 字；内容多就拆段，不要为了凑字数重复同义句。
- 字数按中文字符计算；页码标注不计入，但不要靠堆页码凑数。

## 三、章节归属规则（论文没有对应章节时怎么办）

- `related_work`：论文若没有独立的 Related Work / 相关工作章节，**从 Introduction 中梳理**它引用了哪些工作、把自己与谁对比、差异点是什么；并在叙述开头一句里说明「论文未设独立相关工作章节，以下梳理自 Introduction」。
- `limitation`：从 Conclusion、Future Work、Discussion、以及正文中作者自述的不足（如「未报告 X」「留给未来工作」）里抽取。**若论文确实没有陈述任何局限**，也要写一段说明「论文未陈述局限性」，并给出依据页码；禁止留空、禁止编造。
- `reproduction`：从实现细节、超参数、训练数据、发布时间、检查点与量化产物中抽取；论文没写的写进 `gaps`，不要推测。
- `abstract` 只写论文摘要与引言中作者的自我定位；不要用摘要内容重复充当 `conclusion`。
- 一个片段里没有任何章节内容的章节，不要输出对应条目；不要为了凑齐章节编造内容。

### 禁止「片段腔」

最终文档是把所有片段拼起来的，所以**任何一句谈论「本片段」的话在成品里都是噪音**：

- 禁止出现 `本片段`、`该片段`、`第 X–Y 页未出现`、`以下梳理自……`、`这里只能给出基于本片段的判断` 这类自我指涉的说法。直接写论文内容。
- **本片段缺少某个章节，不要为该章节写叙述**；把这件事写进 `gaps`。
- **参考文献列表、作者贡献、致谢名单不构成任何章节的正文**：不要根据 references 条目写 `related_work`、`conclusion` 或 `reproduction` 叙述，也不要去总结「引用版图」。本片段只有这些内容时，把它们记入 `gaps`，`narrative` 留空。

## 四、narrative 的写作要求

- **读者是人**：写连贯的中文段落，讲清「是什么、为什么、怎么做、结果如何、意味着什么」。禁止把结论写成孤立短句罗列，禁止「本条说明了 X」这类流水账。
- **一段一主题**：每段围绕一个主题；同一主题内容多就拆段，不要把整章写成一坨。
- **正文不要夹大段英文原文**：英文逐字引用只放 `blocks`；叙述里最多保留必要的术语、方法名、指标名。
- **数值必须逐字取自抽取文本**，不许估算、不许换算、不许凭常识补全。
- **消除歧义**：同一句话里出现两个数字时，写清各自属于哪个指标/哪张表，不要让读者猜。
- 方法片段与实验片段是重点，应当明显比其他章节更细。

## 五、字段约束

- `section` 只能取：`abstract`、`background`、`related_work`、`method`、`experiment`、`conclusion`、`limitation`、`reproduction`。
- `topic`：
  - `method` 只能取 —— `模型与流程`、`训练配方`、`关键设计`、`差异与失败场景`；
  - `experiment` 只能取 —— `评测设置`、`主要结果`、`消融与定性分析`、`证据对应与未覆盖问题`；
  - 其他 section 省略 `topic`。`narrative` 与 `blocks` 用同一套 `section`/`topic`。
- `narrative` 的 `text` 里**不要换行**，整段写成一个字符串。

## 六、blocks 是「精选书证」，不是全量清单

- 每个 (`section`, `topic`) 组合**最多 6 条** `claims`，只保留承重结论（支撑正文关键数字、关键设计、关键对比的句子）。
- `page` 必须是**本片段内出现过的页码**，且必须是该陈述真正出处的那一页。
- `quote` 必须是该页英文原文的**逐字连续片段**（可截取，不能改写、不能拼接、不能翻译、不能补空格以外的改动）。找不到可逐字摘录的原文时，把该条移入 `gaps`，不要输出。
- 每条 `claim.text` 只表达**一个**原子结论；不要合并多个结论，不要写因果推测。
- `figures_tables[].kind` 只能取 `figure`、`table`、`equation`。

## 七、绝对禁止

1. 禁止使用本片段之外的论文内容或你自己的先验知识补充结论。
2. 禁止编造实验数值、数据集名称、baseline、相关工作、代码文件名、超参数，也禁止编造图表编号。
3. 禁止把摘要内容当作全文结论重复输出；禁止把参考文献列表、作者与致谢名单当作章节正文，也禁止谈论「本片段」。
4. 禁止忽略文本抽取缺陷：多栏错序、公式丢失、表格错位、图表无法读取时，必须写进 `gaps`。
5. 禁止用「显然」「通常」「众所周知」这类措辞替代论文证据。
6. 禁止在 `narrative` 里写没有页码出处的判断；拿不准的内容放进 `gaps`。
7. 禁止用重复句子或同义改写把章节「凑」到字数下限——达不到下限就把该章节内容如实写清，并把缺口写进 `gaps`。

## 八、输出前自查

- 每段是否只在末尾标了一次页码？句子中间还有 `（第 N 页）` 吗？
- 有没有同一件事在两个 topic 下各写一遍？有就删掉后一处。
- 正文里还有「需人工核对」「数值错位」这类话术吗？有就删掉、把原因移进 `gaps`。
- 每个出现过的章节是否达到第二节的字数下限？`related_work` 与 `limitation` 是否按第三节规则处理？
- 每个 (`section`, `topic`) 的 `claims` 是否 ≤ 6 条？
