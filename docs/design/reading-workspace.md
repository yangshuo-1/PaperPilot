# 论文阅读工作台：HTML 笔记、连续 PDF 与双栏译文

状态：本轮实现已落地并完成收口复核（2026-10-07）。工程检查与真实页面验收记录、以及尚未覆盖的边界统一维护在 `docs/design/roadmap.md` 的阅读工作台改造章节；本文保留设计契约与行为约束。

本文定义阅读工作台改造的诊断依据、目标行为、数据契约与验收边界。分阶段任务、依赖和状态统一维护在 [roadmap.md 的阅读工作台改造章节](roadmap.md#阅读工作台改造)。

本文补充阅读工作台设计；图解 IR、证据校验仍以 [paper-diagrams.md](paper-diagrams.md) 为准，存储分层仍以 [data-organization.md](data-organization.md) 为准。既有产品参考文档用于理解产品背景，本轮阅读布局与对照阅读行为以本文为准。

## 1. 目标

1. 笔记呈现为可阅读、可导航、可导出的 HTML，支持表格、图片、公式和来源引用。
2. 阅读区域充分利用窗口，减少标题、搜索、AI 卡片与侧栏对正文空间的挤占。
3. 图解具有可读的默认字号、缩放和平移能力，并支持专注查看。
4. PDF 连续向下滚动即可阅读下一页，默认适应可用宽度。
5. 对照模式左侧为解析原文，右侧为对应译文；保留图、表、公式及来源定位。

PDF 原版与解析原文是同一阅读工作台的两种视图。原版负责忠实呈现原始排版；对照视图负责按内容块重排、翻译与同步定位。AI 分析笔记与原文解析分别标识，避免把模型总结当作论文原文。

## 2. 实际页面诊断与根因

诊断使用 Playwright MCP，经本地 MCP 客户端连接现有 Chrome CDP，打开真实前端论文页 `/papers/qwen3-vl-2511-21631`，检查 PDF、笔记、图解与译文。以下尺寸来自 1440 × 1000 CSS 像素视口的 MCP 页面快照与元素边界；它们是诊断基线，不是改造后的验收结果。已有截图在诊断结束时清理，实施阶段须重新截图并做视觉复核。

| 问题 | 页面证据 | 根因与代码入口 |
|---|---|---|
| 笔记狭窄、格式表达不足 | 正文约 800px 宽，长文约 37,000px 高；引用行可见原始 `>` | `frontend/src/components/MarkdownView.tsx` 使用简易正则解析，缺少表格、图片、数学公式支持；先转义 `>` 再判断引用导致引用分支失效。`styles.css` 的 `.readerInner` 限宽 860px，扣除 padding 后正文为 800px |
| 内容进入首屏太晚 | PDF canvas 顶部约 y=475；笔记正文约 y=610；图解 iframe 约 y=696 | `pages/PaperPage.tsx` 将返回链接、标题、详情、标签、搜索逐层堆叠；非 PDF 内容上方还有常驻 AI 面板。各层 margin、padding 累积占高 |
| PDF 太小、不能连续翻页 | 42 页论文只显示一个 canvas，默认页面约 685px 宽；无可靠目录仍保留 240px 侧栏 | `PdfReader.tsx` 只维护当前页并替换单 canvas，固定初始 scale=1.15；`pdf-reader.css` 固定侧栏与 28px 舞台内边距，没有适应宽度计算和连续页面容器 |
| 图解小且空间浪费 | iframe 约 1146 × 640px，内部图解约 263 × 524px | `components/diagram.css` 限制 iframe 高度；实际产物画布为 526 × 1048px，内部 fit 脚本同时受宽、高约束，缩至约 0.5；纵向长链布局、190px 产物列表与上方信息进一步挤占空间 |
| 译文不是左右对照 | 原文在上、译文在下；存在原始 `##` 文本；页面有大量重复 key 警告 | `components/PaperPanels.tsx` 的 TranslationPane 直接显示字符串；`.chunk` 未采用双栏；以段落 hash 作为 React key，重复段落具有相同 key |
| 图表公式不能保真 | 对照接口只有 source、translated、hash，无内容类型和页码 | `stores/documents.py` 从 `latex_plain.txt` 读取文本；`latex.py::cleanup_text` 明确删除 figure、equation、algorithm 等环境和数学表达式，表格结构也没有被保存为结构化内容块 |
| 翻译结果难以稳定对齐 | 展示与生成分别处理段落 | `stores/documents.py::translation` 按空行切分，`generate_translation` 调用 `llm.py::split_paragraphs`，两者切分逻辑不一致；仅凭文本 hash 无法表达重复段落的位置、页码和版本 |

边界说明：重复文档标题已在笔记页观察到；实际重复 key 警告来自译文列表，不能据此断言笔记列表也有相同错误。LaTeX 清洗的显式删除列表不含 table 环境，表格问题是结构未被保留，不能概括为直接删除所有 table 环境。

原版 PDF canvas 已能够呈现原有图表公式；信息损失发生在纯文本解析与翻译输入链路。增加 HTML 后缀或调整 CSS 无法恢复已丢失的源结构。

## 3. 页面布局

- 阅读页使用独立的宽屏布局，侧边留出必要边距；主内容占据剩余视口高度。
- 标题、模式切换与常用操作集中在紧凑工具栏；详情、搜索和 AI 按需展开。
- 目录侧栏可完全收起；无可靠目录时不持续占据固定 240px。
- 使用单一明确的主要滚动容器，减少整页与内部卡片同时滚动。
- 普通文字保持合理行长；多余宽度用于目录、证据或双栏，表格、图片、PDF 和图解可使用完整内容宽度。
- 原版 PDF、对照阅读、笔记和图解保留各自滚动位置，切换后可返回原位置。
- 1280px、1440px 桌面视口与约 390px 移动视口分别验收。移动端切换原文/译文或按块上下排列，维持对应块位置。

## 4. HTML 笔记

- 兼容已有 Markdown；以完整语法解析生成受控 HTML，覆盖标题、嵌套列表、引用、表格、代码、图片及数学表达式。
- 全文解析笔记必须**图文并茂**：论文自身的图、表、公式由确定性代码从 LaTeX 源码装配进「图表与公式」一节，位置在摘要之后；图片走受限资产接口，数值不经模型改写。装配不了的表（旋转表头等）不做近似转换，改为 PDF 页码链接 + 原始 LaTeX 折叠块。
- 排版规则：段末标注页码并按页合并（`（第 3–4、6 页）`）；近重复段落只保留一次；正文不出现「需人工核对 PDF 表格」这类陈旧话术（真实抽取缺陷保留在「未确认信息」）。
- HTML 是正式阅读与导出格式。确定性渲染已有 Markdown 不需要重新调用模型；使用统一渲染规范避免页面和导出效果分离。渲染器升级时可用 `/api/papers/{id}/analysis/codex?reuse_chunks=true` 复用既有分片重渲染，元数据记录正文实际使用的 prompt 版本。
- 加入章节目录、稳定标题锚点、文档选择器和来源页码跳转。重复标题显示可区分的文件名或版本信息。
- 来源摘录可展开核对；正文不持续展示路径、任务 ID 等运行细节。
- HTML 与资源 URL 经过白名单处理，禁用任意脚本和事件属性；图片通过受限论文资产接口读取。
- 数学渲染器及字体随应用或导出产物提供；离线打开导出 HTML 时公式和图片仍可见。
- 不从纯文本猜测缺失的图表或公式。无法恢复的内容明确关联原版 PDF。笔记不内联图解 iframe 或内联 SVG：前端清洗策略会剥离它们，图解以「图解」标签页的交叉链接呈现。

## 5. 连续 PDF 阅读

- 页面列表按原始页序排列，向下滚动自然进入下一页。
- 只渲染视口及邻近页面，使用稳定占位尺寸；离屏 canvas 可释放，避免整篇高分辨率页面常驻内存。
- 通过容器宽度和 PDF 页尺寸计算默认缩放；提供适应宽度、实际尺寸、手动缩放。
- 保留原始页边距与完整内容；可选裁边需要独立交互和恢复入口，不默认裁掉论文内容。
- 当前页由主要可见页面决定；阅读进度节流保存。目录、搜索、图解证据和笔记引用均滚动到目标页。
- 阅读器只能滚动自身的页面容器，不得使用会把窗口一起带动的定位方式；否则每次打开论文或跳页都会把标题栏与工具栏顶出可视区。
- 取消渲染是正常控制流：页面被释放或滚出视口时渲染任务会被取消，其 promise 必须在创建处就被观察，否则会抛未捕获的 `RenderingCancelledException`。
- 页码属于页面组件及选区，不能继续用全局单页状态标记所有选择；高亮、文本选择与页码跳转需要回归验证。
- 处理快速滚动、缩放与切换论文时的渲染取消，避免旧任务绘制到新页面。

## 6. 结构化原文与翻译契约

以下为目标契约，具体 schema/API 在路线图 R1 阶段冻结。

### 文档与内容块

文档记录 `schema_version`、`document_version`、`parser_version`、来源类型、解析质量与警告。按阅读顺序保存内容块：

| 字段 | 含义 |
|---|---|
| `block_id` | 文档版本内稳定且唯一的位置标识；重复文本也有不同 ID |
| `order` / `section_id` | 阅读顺序与章节归属 |
| `type` | heading / paragraph / figure / table / equation / caption 等 |
| `source_text` / `source_html` | 原文文本与受控 HTML；不包含模型改写 |
| `page_start` / `page_end` / `bbox` | 有可靠映射时记录 PDF 页码范围、页内区域 |
| `asset_path` / `latex` / `mathml` | 图表资源或数学表达式，按块类型提供 |
| `source_anchor` | 来源文件、章节或原始 DOM 标识，便于核对 |

arXiv HTML/LaTeX 结构不天然具有 PDF 页码。页码映射必须标明可靠性，无法匹配时保留章节定位或提供 PDF 原页入口，禁止伪造页码。纯 PDF 解析不能只依赖文本抽取：无法可靠识别的图表公式使用带页码的原页或区域渲染作为保真回退，且在页面中明确显示。

### 翻译记录

- 以 `document_version + block_id + source_hash + prompt_version` 关联译文，并记录 generator/model 元数据与状态。
- 展示、任务生成、缓存读取共用同一内容块列表，避免使用两套段落切分逻辑。
- 文本和图注可翻译；公式、图像与表格数值保持来源内容。表格文本翻译必须保持行列对应。
- 旧翻译缓存仅在源文精确匹配且来源明确时复用；文本 hash 可用于复用，不作为位置 ID。
- 任务按未完成块继续，已完成块逐步落盘；支持取消、失败重试、版本失效和进度显示。
- 版本变化标记 stale，不自动重新发起成本任务。

### 存储边界

源文件保持不可变。确定性结构解析、页图及 HTML 渲染写入 `derived/`；模型译文、分析内容写入 `results/` 并带版本信息；用户导出写入 `exports/`。所有写入通过系统流程完成，采用原子写入和 manifest 审计；历史布局只读兼容，不批量移动或手工改写生成物。

## 7. 双栏对照

- 左侧显示解析原文，右侧显示对应译文，以相同 block_id 对齐。
- 提供可拖动分隔线、同步滚动开关与章节定位；按块锚点同步，不使用总高度百分比粗略对应。
- 图、表、公式在所属位置保留，可跨栏展开或放大；图注显示原文与译文，提供原 PDF 来源入口。
- 未翻译、失败、过期和解析不完整分别显示状态，保留原文及资产。
- 长文按章节或内容块虚拟化；异步图片加载、公式排版及译文高度变化后保持当前位置。
- 同一时刻只挂载一种布局：窄视口挂载逐块堆叠版，宽视口挂载双栏版。两套布局同时进 DOM 会让块级渲染与清洗开销成倍增加。
- 结构化块携带的 HTML 必须经过与 Markdown 相同的数学排版与白名单清洗路径，否则正文里的 `$...$` 会以原始 LaTeX 显示。
- 后端下发的译文是纯文本，必须转义后再包成 HTML；未转义的 `<` 或 `&` 会被前端清洗器当作标签丢弃。
- tier1 来源没有可靠 PDF 页码时，块级定位回落到章节标题；不允许用恒等的行号区间或伪造页码充当定位。

## 8. 图解阅读

- 外层 iframe 使用阅读工作台剩余高度，产物列表改为紧凑切换或可收起面板。
- 图形保留自身坐标与布局尺寸，通过视口变换展示；取消强制塞入整屏高度导致的默认微缩。
- 提供可读默认比例、适应宽度、全图概览、100%、缩放、平移与全屏查看。全图概览可能较小，需明确可切回可读比例。
- 根据图形拓扑和窗口比例选择布局；横向长链也可能超宽，不能把固定横向布局当作通用解法。
- 默认可读模式节点标题目标至少 13 CSS px；边标签目标至少 11 CSS px。文字过长可展开详情，避免静默截断关键内容。
- 保留节点与边的证据交互。无可靠页码时显示章节/摘录，不生成“第 0 页”跳转。
- 既有 IR 经新渲染器重新生成 HTML，记录 generator_version；不要求重新调用模型生成相同语义内容。产物 HTML 自带渲染器版本标识，且必须监听前端的视口指令，否则前端缩放控件对该产物完全失效。
- 渲染器版本变更后必须重新产出 `results/diagrams/*.html`（`scripts/render_diagrams.py --apply`），并同步 `manifest.json` 与 `runs.jsonl`；只改渲染器不重渲会让仓库内产物与代码不一致。
- 画布比画框窄时应居中而不是贴左，否则宽屏下图形只占一侧、另一侧大面积留空。缩放通过外层尺寸占位元素表达，保证居中与滚动同时正确。
- 更新 `paper-diagrams.md` 中的呈现约束，保留既有 IR 和逐字证据校验规则。

## 9. 验收原则

必须同时具备代码检查、真实 API、MCP 浏览器操作和截图视觉复核。测试通过或 DOM 中存在节点不能单独证明阅读效果合格。

- 使用有实际 PDF、笔记、图解与译文的论文；另外覆盖缺少 LaTeX、解析降级和未翻译状态。
- 覆盖公式、图片、表格及跨页文本，逐项核对原版 PDF；无法完整解析时检查保真回退。
- 桌面默认阅读模式中，主要内容视口目标占可视高度至少 75%，通过实际元素边界测量；不靠缩小正文达标。
- 连续 PDF 至少跨越三页滚动，并验收页码更新、证据跳转、选择高亮和位置恢复。
- 双栏验收原文/译文块对应、缺失译文、长度差异、图片加载后的同步定位及重复文本唯一 ID。
- workflow 与 data_flow 均截图，检查节点、边、文字、重叠、缩放和证据弹层。
- 检查页面级横向溢出、控制台错误、重复 key；长文不能一次性渲染全部高分辨率 PDF canvas。

具体阶段门禁及项目命令见 [roadmap.md](roadmap.md#阅读工作台改造)。
