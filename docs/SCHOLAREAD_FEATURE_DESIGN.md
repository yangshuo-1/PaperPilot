# ScholarRead 功能设计参考

## 1. 文档目的

本文档记录 ScholarRead 主站可观察到的产品能力，并将其中适合 `paper_valt` 的部分转化为本地优先的功能设计建议。

本文档只讨论主站内部的产品能力，不把以下内容纳入本轮设计范围：

- Zotero 集成
- Bookmarklet 和浏览器扩展
- Word/WPS 插件
- 多端同步
- 第三方登录和身份绑定
- 会员、支付和额度商业化
- 外部期刊网站的访问权限管理

本文档不是 ScholarRead 的技术实现复刻，也不假设其所有后端能力都可在本地直接获得。对于依赖云端模型、云端解析或外部数据源的能力，本文档只保留产品交互和数据边界。

## 2. 产品判断

ScholarRead 的核心不是论文收藏夹，而是一条连续的研究工作流：

```text
Library -> Reader -> AI -> Project
```

四层职责不同：

- `Library` 管理全部论文资产和组织关系。
- `Reader` 承载沉浸式阅读、定位、进度、翻译、笔记和高亮。
- `AI` 在论文或选中文本上下文中提供解释、问答和重点提取。
- `Project` 把论文、普通文件、AI 产物和持续会话组织成长期研究工作空间。

`paper_valt` 当前已经覆盖 Library 的基础组织、论文详情、LaTeX、翻译、Codex 分析和导出能力。下一阶段的重点应从“增加更多论文元数据”转向“把阅读行为和研究过程做成一等数据”。

## 2.1 已确认的产品决策

以下决策已作为下一阶段的实现约束：

1. **Phase 1 聚焦 PDF Reader**：先完成 PDF 打开、分页、阅读进度、继续阅读和基础定位，不继续扩展 Library 的广度。
2. **采用成熟 PDF viewer**：替换当前只能提供外层预览的 iframe，使系统能够获得页码、文本层和选区事件，为高亮和笔记建立基础。
3. **阅读状态与解析状态分开**：阅读状态使用 `unread / reading / read`；解析状态独立记录索引、抽取、翻译、分析和失败等处理阶段。
4. **Reading List 使用独立关系**：不复制论文数据，论文移出 Reading List 不会从 Library 删除。
5. **第一版锚点采用页面加引文**：至少保存 `paper_id + page + quote + document_version`；文本 offset 能可靠获取时再作为增强字段。
6. **Project / Session 暂不进入当前实现**：保留关系设计和未来挂载点，待 Reader 与本地笔记闭环稳定后再实现。

## 3. 功能分层

### 3.1 Library：论文资产管理

#### 核心能力

- 展示全部论文资产。
- 按文件夹路径查看论文。
- 新建、重命名、删除和移动文件夹。
- 搜索或创建文件夹。
- 列表视图和卡片视图。
- 按加入时间、更新时间和阅读时间排序。
- 按未读、阅读中、已读筛选。
- 按全文可读、仅链接筛选。
- 单篇速览、编辑元数据、移动、删除。
- 多选论文并批量移动或更新状态。
- 空库和空文件夹状态中提供明确的导入入口。

#### 设计原则

1. 文件夹是组织关系，不是论文本体。
2. 阅读状态是用户工作状态，不应覆盖论文的解析状态。
3. 论文的原始元数据和用户管理元数据分开存储。
4. 批量操作必须显示选中数量，并提供可恢复的结果反馈。
5. 搜索、筛选和文件夹选择应组合使用，不能互相覆盖造成隐式过滤。

### 3.2 Reading List：近期阅读队列

`Library` 和 `Reading List` 建议在产品模型上分开：

- `Library` 表示用户拥有或保存的全部论文。
- `Reading List` 表示用户近期准备处理的论文集合。

第一版不需要复制论文数据。可以通过用户元数据派生 Reading List：

- `read_status = unread`
- 用户显式加入待读队列
- 最近导入但尚未开始阅读的论文
- 被用户标记为重点的论文

Reading List 需要支持：

- 过滤未读和阅读中论文。
- 按优先级或最近加入时间排序。
- 快速进入继续阅读。
- 从队列中移除，但不删除 Library 中的论文。

### 3.3 Paper Detail：论文详情和速览

论文详情页负责回答“这篇论文是什么”和“我是否应该现在读它”。

#### 元数据

- 标题和短标题。
- 作者。
- 年份、期刊或来源。
- DOI、arXiv ID、来源 URL。
- 本地 PDF 状态。
- 全文可读状态。
- 分析状态。
- 阅读状态和阅读进度。
- 标签和所属文件夹。

#### 内容入口

- Abstract。
- Contents / 目录。
- Figures / Tables。
- Video（存在时）。
- 分析文档。
- LaTeX 正文或解析文本。
- 立即阅读。
- 从上次位置继续阅读。

#### Quick Glance

速览应当是轻量的预览，不替代完整 Reader：

- 摘要。
- 作者和年份。
- 论文状态。
- 图表缩略信息。
- 当前阅读进度。
- 立即阅读。
- 加入或移出 Reading List。

### 3.4 Reader：沉浸式阅读工作台

Reader 是后续设计的核心。它不能只是一个 PDF iframe 和 Markdown 文档切换器。

#### 阅读模式

- 原始 PDF 模式：保留论文原始版面和分页。
- 普通 Reflow 模式：将文本转换为连续阅读布局。
- AI Reflow 模式：在可用时改善复杂版面、公式和图表的阅读体验。

本地 MVP 可以先实现原始 PDF 模式和轻量文本阅读模式，不承诺实现完整 AI Reflow。

#### 阅读控制

- 缩放。
- 适应宽度。
- 适应高度。
- 恢复默认缩放。
- 字体和字号设置（仅文本或 Reflow 模式）。
- 从头阅读。
- 继续上次阅读位置。
- 当前页 / 总页数。
- 阅读进度保存。

#### 侧栏

Reader 侧栏建议包含以下入口：

- Contents：章节目录。
- Figures：图表列表。
- Highlights：高亮列表。
- Notes：笔记列表。
- Highlights & Notes：合并视图。
- AI Takeaways：AI 重点。
- AI Chat：当前论文问答。
- Paper Info：论文元信息。

侧栏条目必须能够定位回原文页面、段落或区域。没有定位能力的列表只能作为详情页信息，不应伪装成 Reader 导航。

### 3.5 选区操作：从阅读到理解

在文本选区上提供上下文操作：

- 复制原文。
- 高亮。
- 添加笔记。
- Explain：解释选中内容。
- Ask AI：基于选中内容提问。
- 翻译。
- 查看原文。
- 重新翻译。
- 查看关联笔记。

推荐交互闭环：

```text
选中文本 -> 解释/翻译 -> 高亮或写笔记 -> 保存锚点 -> 从侧栏定位回来
```

本地第一版可以先实现复制、高亮和笔记；Explain、Ask AI 和选区翻译属于后续 AI 能力。

### 3.6 Highlights 和 Notes：阅读行为数据

#### Highlight

高亮记录至少需要：

- `paper_id`
- `document_id` 或 `source_type`
- 页面编号或段落编号
- 选中文本
- 选区起止位置（能获得时）
- 颜色或样式
- 创建时间
- 最近更新时间

#### Note

笔记记录至少需要：

- `paper_id`
- 关联的 highlight 或 anchor
- 页面编号或段落编号
- 引用原文
- 用户笔记内容
- 创建时间
- 更新时间

#### 约束

- 笔记不能只有纯文本，必须尽量保留原文锚点。
- 原始 PDF、解析文本和翻译文本的锚点类型要区分。
- 当源文件重新解析后无法恢复锚点，应显示“需要重新定位”，不能静默指向错误内容。
- 删除论文时必须明确处理其高亮和笔记：级联删除或保留为孤立记录，不能隐式决定。
- 第一版只支持单用户本地存储，不考虑多人冲突。

### 3.7 Translation：全文和局部翻译

#### 全文翻译

- 选择目标语言。
- 翻译正文和目录。
- 原文/译文对照。
- 显示翻译覆盖进度。
- 支持继续翻译和重新翻译。
- 明确显示任务状态、失败原因和不可翻译原因。

#### 局部翻译

- 选中文本后翻译。
- 复制翻译结果。
- 显示原文和译文。
- 允许重新翻译。

#### OCR 翻译

OCR 截图翻译属于扫描版 PDF 的补偿能力，依赖 OCR 和模型服务，不纳入本地 MVP 的硬要求。

#### 设计约束

- 翻译缓存与源文段通过稳定 hash 关联。
- 源文段改变后，旧译文不能被当作新译文直接复用。
- 翻译不可用时，原文阅读和笔记功能必须继续可用。
- 翻译任务是异步任务，不阻塞 Reader 主界面。

### 3.8 AI：从论文问答到研究辅助

#### Paper Chat / Copilot

- 当前论文作为上下文。
- 可选中多篇论文作为参考。
- 浮动窗口或侧栏模式。
- 显示回答生成状态。
- 支持后续问题建议。
- 支持清空当前对话。
- 显示引用论文数量和上下文范围。
- 对页数、文件大小、模型不可用等限制给出解释。

#### AI Takeaways

AI Takeaways 可以识别并标记：

- 研究目标。
- 方法设计。
- 主要结果。
- 创新点。
- 限制或风险。

每个重点必须带有来源锚点，至少定位到页面或章节。没有来源定位的 AI 重点只能标为“未验证建议”，不能和论文原文事实混合。

#### Research Agent

Research Agent 是跨论文、跨文件的高层工作流：

- 从研究问题开始。
- 检索和筛选论文。
- 比较方法。
- 设计实验。
- 分析结果。
- 生成综述或研究草稿。
- 将产出保存到 Project 工作区。

这部分不应在 Reader MVP 中直接实现。它需要 Project、Session、文件上下文和任务状态作为基础设施。

### 3.9 Project：长期研究容器

Project 不等同于 Library 文件夹：

- 文件夹回答“论文如何分类”。
- Project 回答“围绕什么研究目标持续推进”。

Project 可以包含：

- 关联论文。
- 普通文件。
- 草稿和笔记。
- 数据表。
- 图片。
- AI 生成结果。
- 多个研究 Session。
- 项目级设置和目标。

#### 工作区能力

- 浏览文件树。
- 预览文件。
- 创建目录。
- 重命名。
- 移动。
- 导出。
- 删除。
- 显示缺失资源。

PDF 论文仍然属于 Library 的论文资产。Project 通过关系引用论文，不应复制 PDF 文件。

### 3.10 Session：持续执行单元

Project 内的 Session 是围绕一个研究目标持续推进的执行单元。

Session 至少需要：

- 标题或目标。
- 所属 Project。
- 当前状态。
- 创建时间。
- 最近活动时间。
- 下一步。
- 关联论文。
- 关联工作区文件。
- 消息历史。
- 任务运行状态。
- 产物列表。

Session 的基础能力：

- 新建。
- 继续。
- 重命名。
- 删除或归档。
- 移动到其他 Project（需要明确关系语义）。
- 加载历史消息。
- 启动运行。
- 取消运行。
- 显示工具调用结果。
- 显示权限请求并允许批准或拒绝。
- 将 AI 结果保存为 Project 文件。

第一阶段不要把 Session 做成完整治理系统。先保证执行状态、上下文来源和产物关系可见；关闭、归档、替代、拆分和智能建议属于后续治理阶段。

## 4. 用户主流程

### 4.1 从导入到阅读

```text
导入论文
  -> 解析元数据
  -> 保存到 Library
  -> 选择文件夹或 Reading List
  -> Quick Glance
  -> 立即阅读或稍后阅读
```

关键状态：

- `importing`
- `indexed`
- `full_text_available`
- `conversion_failed`
- `needs_review`

### 4.2 从阅读到笔记

```text
打开论文
  -> 恢复上次位置
  -> 浏览目录或图表
  -> 选中文本
  -> 高亮/写笔记/翻译
  -> 保存锚点
  -> 侧栏回看并定位
```

关键要求：阅读进度、笔记和高亮都应独立保存，任何一个能力失败都不应让论文无法打开。

### 4.3 从论文到 AI

```text
打开论文
  -> 选择整篇论文或选中文本
  -> Ask AI / Explain
  -> 生成回答
  -> 标记来源
  -> 保存回答到 Project 或文档
```

AI 回答必须区分：

- 论文直接支持的内容。
- 基于论文的推断。
- 需要用户进一步核验的内容。

### 4.4 从问题到 Project Session

```text
提出研究问题
  -> 创建或选择 Project
  -> 关联论文和工作区文件
  -> 创建 Session
  -> 运行 AI 任务
  -> 产生消息、决策和文件产物
  -> 继续下一次工作
```

Project 保存长期上下文，Session 保存当前执行现场，论文和文件作为可引用资源存在。

## 5. 当前 paper_valt 对照

### 已具备

- 本地论文索引和刷新。
- 标题、arXiv、仓库 URL、标签搜索。
- 标签过滤。
- 星标、阅读状态、阅读进度字段和最近阅读时间字段。
- 文件夹树和基础 CRUD。
- 表格/卡片视图。
- 批量星标、状态更新和文件夹移动。
- arXiv 导入和 PDF 下载。
- Quickview 摘要和图表。
- PDF 内嵌预览。
- Markdown 分析文档阅读。
- LaTeX 下载、解析和预览。
- 异步翻译任务和段落缓存。
- Codex 全文解析任务。
- Markdown、BibTeX、GB/T 7714、APA 导出。

### 主要缺口

- PDF 阅读器无法向前端回传真实页码和选区。
- 阅读进度目前不能可靠地从 PDF 阅读行为派生。
- 没有 Contents 和 Figures 的统一定位模型。
- 没有高亮和锚点笔记。
- 没有论文内全文搜索。
- 没有当前论文上下文的 Ask AI。
- 没有 AI Takeaways 的来源锚点模型。
- 没有 Reading List 的独立产品视图。
- 没有 Project、工作区文件和 Session 模型。
- Quickview 仍偏摘要和图表，缺少继续阅读和状态操作的完整闭环。

## 6. 分阶段实现建议

### Phase 1：PDF Reader 基础闭环

目标：围绕本地 PDF 建立可持续的阅读基础，不在这一阶段实现完整的 Reflow、笔记或 AI 能力。

范围：

- 引入成熟 PDF viewer，替换当前无法回传阅读事件的 iframe 预览。
- 支持 PDF 分页、当前页、总页数和基础缩放。
- 保存当前页、总页数和阅读进度。
- 支持从上次位置继续阅读。
- 保留文本层和选区事件接口，为 Phase 2 的高亮和锚点笔记提供能力基础。
- 解析并展示 Contents；无法从 PDF 可靠解析时提供局部降级。
- 解析并展示 Figures/Tables 索引；至少保存名称、页码或来源位置。
- 详情页和 Reader 之间支持继续阅读。
- 所有加载失败、解析失败和缺失内容都有局部降级。

非目标：

- AI Reflow 或完整 PDF 重排。
- OCR。
- 高亮和本地笔记持久化。
- 论文内全文搜索。
- Paper Chat、AI Takeaways 和选区 AI。
- Project / Session。
- 云端同步。
- 多人协作。

验收标准：

- 打开论文后可以恢复上次阅读位置。
- 使用成熟 viewer 能读取当前页和总页数；如果某类 PDF 不支持，必须显示不可用原因。
- Reader 中可以从目录跳转到章节，或明确显示目录不可用。
- 图表列表至少能显示名称、页码或来源位置。
- viewer 提供可供后续使用的文本层和选区事件接口。
- PDF 不可解析时仍可以打开原始 PDF 或现有 Markdown 文档。
- 阅读状态和解析状态在列表、详情和持久化数据中不会互相覆盖。

### Phase 2：本地高亮和锚点笔记

目标：把阅读行为沉淀为可回看的本地知识。

范围：

- 文本选区高亮。
- 创建、编辑、删除笔记。
- 页面/段落/选区锚点。
- Highlights、Notes、Highlights & Notes 侧栏。
- 点击笔记定位回原文。
- 源文档变化后的失效锚点提示。
- 本地 JSON 或 SQLite 持久化，保持单用户。

非目标：

- 多人编辑。
- 跨设备同步。
- 复杂语义检索。
- 自动生成全部笔记。

验收标准：

- 高亮和笔记重启后仍然存在。
- 笔记带有原文摘录和定位信息。
- 删除或重新解析源文档后，不会静默指向错误位置。
- 论文删除时，高亮和笔记的处理策略可见且一致。

### Phase 3：论文内 AI 辅助

目标：把 AI 从离线全文解析任务扩展到阅读中的即时辅助。

范围：

- 当前论文 Ask AI。
- 选中文本 Explain。
- 选中文本翻译。
- AI 回答显示来源范围。
- AI Takeaways 的任务状态和来源锚点。
- 选择多篇论文作为上下文。
- 回答可保存为 Markdown 文档。

非目标：

- Research Agent。
- Deep Research。
- 自动修改论文内容。
- 无来源的自由生成摘要。

验收标准：

- AI 请求失败不影响 Reader 和笔记。
- 用户可以区分论文原文、AI 推断和未核验内容。
- AI 回答至少记录论文 ID、文档版本和上下文范围。
- 生成的结果可以保存并在详情页或 Project 中查看。

### Phase 4：Project 和 Session

目标：把论文阅读和研究任务连接成长期工作流。

范围：

- Project 创建、列表、设置和目标。
- Project 关联论文。
- Project 工作区文件树。
- Session 创建、继续、重命名、历史和运行状态。
- Session 关联论文、文件和产物。
- Codex/AI 任务状态与 Session 关联。
- 产物保存到 Project 工作区。

非目标：

- 复杂 session 治理规则。
- 自动拆分和合并。
- 多代理协作。
- 跨设备同步。

验收标准：

- 用户可以从一篇论文进入一个 Project Session。
- Session 恢复时能看到目标、关联资源、最近状态和下一步。
- AI/Codex 产物不会只停留在运行日志中，可以作为文件或文档访问。
- Project 删除、Session 删除和论文删除的关系处理是明确的。

### Phase 5：治理和智能化

目标：在执行数据稳定后，提供 session 和研究资料治理。

候选范围：

- Session 状态机。
- close / archive / stale 候选。
- Session summary 和 handoff。
- 下一步建议。
- 关联关系识别。
- Project 内的研究进度视图。
- 基于高亮、笔记和 Session 产物的研究摘要。

这一阶段必须建立在 Phase 4 的真实使用数据上，不应提前设计成全自动管理器。

## 8. 产品边界和风险

### 原始内容不可覆盖

PDF、原始 LaTeX 和外部元数据属于 source data。用户标签、阅读状态、笔记和高亮属于 overlay 或本地派生数据。任何用户操作都不能回写破坏原始论文内容。

### 定位必须可解释

页码定位、段落定位和文本 offset 的可靠性不同。系统应记录定位类型和文档版本，在定位不可靠时显示降级状态。

### AI 输出必须带来源边界

AI 摘要、重点和问答不得与论文原文混在同一个无标识文本流中。每条 AI 结果应记录来源论文、文档版本和上下文范围。

### 任务状态必须局部失败

翻译、AI、解析和索引任务失败时，不能让 Library 或原始 Reader 全部不可用。任务状态应独立显示，并提供重试或继续操作。

### 本地优先

Phase 1 到 Phase 4 均默认单用户本地环境：

- 不设计同步冲突解决。
- 不设计多人权限。
- 不依赖外部账号。
- 数据格式可迁移，但不为云端部署提前引入复杂抽象。

## 9. 推荐实施顺序

```text
Reader adapter
  -> page/progress persistence
  -> contents/figures navigation
  -> local highlights and notes
  -> in-paper search
  -> paper-context AI
  -> Project
  -> Session
  -> session governance
```

推荐的第一份可执行计划应只覆盖 Phase 1：Reader 基础闭环。原因是它会确定后续高亮、笔记、AI 来源锚点和 Session 上下文所依赖的文档定位模型。若跳过这一步，后续功能会分别使用页面、Markdown 行号和 PDF offset，最终难以统一。

## 10. Phase 1 退出标准

Phase 1 只有满足以下条件，才适合进入高亮和笔记：

- 原始 PDF 可以稳定打开。
- 当前页和总页数有可靠来源，或明确标记为不可用。
- 阅读进度可以保存和恢复。
- 目录条目能够定位到页面或章节。
- 图表条目能够定位到页面或资源。
- PDF 解析失败时，原始 PDF 和已有 Markdown 文档仍可访问。
- Reader 文档版本能够被后续 Anchor 引用。
- 加载、转换、定位失败均有可见的局部状态。

满足这些条件后，`Highlight`、`Note`、`AI Takeaway` 和 `Session` 才能共享同一套稳定的文档位置语义。
